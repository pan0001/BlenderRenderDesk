# v3.5.0 — 软件内检查、下载与安装更新

以后更新不用再手动去 GitHub 找安装包：打开“软件设置 → 软件更新”，查看新版说明、下载更新包，再点击“安装并重启管理器”。

- 启动时在后台检查本项目的 GitHub 正式 Release；发现新版显示提示，也可关闭自动检查或手动检查。
- 显示当前版本、新版本、发布说明、下载进度及失败原因；查询和下载在独立线程进行。
- 验证附件大小、SHA256SUMS 与 GitHub 提供的摘要，检查解压路径和体积；校验失败不安装。
- 下载完成后由用户点击安装。只重启管理器，保留任务、设置、访问密钥和自定义数据目录；正在运行的 Blender 继续渲染。
- Windows 替换程序后验证启动，新版未正常启动时尝试回退并重新打开旧版；旧程序保留为旁边的备份目录。
- 本地桌面与远程网页共用更新界面和访问密钥验证。远程管理服务以原启动参数恢复。
- 添加 `scripts/package_release.py`，统一生成供手动发布的 Windows 包、源码包、校验文件和发布说明。
- 包含 v3.4.0 的外层分批脚本识别、整套计划管理及后续 Blender 自动归属功能。

## 使用与发布

v3.3.x / v3.4.0 尚无内置更新，需要先完整解压本版 Windows 包，关闭旧管理器后启动新版。之后发布比当前版本更高的正式 Release，软件便可检测到。

本版更新方式是**自动下载完整 Windows 包**，不是文件差分增量，也不支持断点续传。下载完成后仍需点击安装，不会自行强制重启。

手动发布到 `pan0001/BlenderRenderDesk` 时，使用标签 `v3.5.0`，上传 `BlenderRenderDesk-v3.5.0-Windows.zip`、`BlenderRenderDesk-v3.5.0-source.zip` 和 `SHA256SUMS-v3.5.0.txt`。发布说明可直接复制本文件。后续版本保持相同命名规则并递增版本号；只同步源码、草稿或预发布不会触发正式更新。

## 验证

- 84 项后端 / API 测试通过，包括版本比较、不降级、下载失败可重试、校验不一致拒绝、路径穿越 / 链接 / 重复文件拒绝、异步检查、鉴权与跨站拒绝、自定义数据目录和重启参数保留。
- Windows 程序副本在隔离目录分别以网页服务和原生桌面模式完成实际目录替换、新版启动确认和故障回退。真实 Blender 渲染在两次替换期间保持相同 PID、持续增加完成帧；同一任务 ID、访问密钥和自定义目录数据保留。
- 原生 pywebview EXE 启动就绪、启动清理完成队列且保留图片验证通过。
- 浏览器验证检查更新、下载进度、安装入口、自动检查开关和纯文本发布说明。新版本演示使用隔离数据，不曾上传虚构 Release。
- GitHub 正式接口只读验证通过；验证时最新发布为 v3.3.1，正确拒绝降级。未对真实线上新版执行下载安装，也未上传本版。

## 实际限制

- 内置安装目前限 Windows 完整成品包，并要求程序及其上级目录可写。源码运行显示版本状态，仍需手动更新源码。
- 数据目录、任务工程、脚本或输出在软件目录内部时，拒绝替换，避免随旧程序一起移入备份；软件应单独解压存放。
- 更新期间管理页面和 frpc 短暂断开；原地址不变时页面自动重连。frpc 需启用随管理器启动，或更新后手动启动。
- 管理器退出期间，依赖管理器的暂停检测、定时与自动恢复暂不可用。Blender 和外层脚本继续运行；不要在等待按帧暂停的关键时刻安装更新。
- 自动回退只覆盖替换或启动就绪失败，不验证新版所有业务功能，也不是数据库迁移回滚。未来有不兼容数据迁移的版本需另行提供迁移方案。
- 旧版本备份与安装阶段临时目录暂不自动清理。确认更新正常后可自行清理备份；重开软件前未安装的下载包可能需要重新下载。
- GitHub 连通性、接口限流、企业策略禁用 PowerShell 或杀毒软件锁定目录可能阻止更新；失败后可重试或手动解压完整包。SHA256 用于完整性检查，不代替独立代码签名。

实现依据：[GitHub Release API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release) 与 [Release 附件 API](https://docs.github.com/en/rest/releases/assets#get-a-release-asset)。
