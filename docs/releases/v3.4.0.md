# v3.4.0 — 自动识别并接管分批渲染脚本

解决“工程有 1200 帧，完成 60 帧就显示完成，随后又出现新 Blender”的问题：一键接管会继续检查 Blender 的 Python 父进程，识别受支持的外层调度脚本，将各批次作为一个完整计划管理。

- 自动识别脚本路径、启动参数、完整帧范围、批次数和每批日志，无需手动输入。
- 后续 Blender 更换 PID 时自动归入同一任务，进度按整套计划统计；详情显示外层脚本、调度 PID 和当前批次范围。
- 旧的单批任务可升级为整套计划，复用原任务记录；已管理的单批进程发现 Python 父脚本时提供“接管整套脚本”按钮。
- 暂停先冻结外层调度，防止启动下一批，再等待新完整帧保存并退出外层脚本及 Blender。继续时使用原 Python 程序重启原脚本，跳过完整帧，保留脚本最后的合成与校验流程。
- 原脚本写入磁盘的各批次日志可在任务中查看；暂停后重启会记录外层脚本输出及退出码。
- 图像全部完成而脚本仍运行时显示“等待脚本后处理”；等待期间不发送完成通知、不清理任务。
- 仍按单批管理的任务，局部范围完成时显示“本批已完成”，Bark 通知也区分本批完成。

## 支持范围与限制

支持直接运行 `.py` 的 Python 父进程，顶层固定 `range` 分批循环、一个 `subprocess.Popen` 启动点、`while 子进程.poll() is None` 顺序等待，以及同工程、同场景、同目录、固定步长的 PNG 渲染脚本。当前用户的 20 批、1–1200 帧脚本已只读识别验证。识别只解析源码，不运行脚本；首次接管需要至少一个对应 Blender 子进程仍在运行。

不支持任意 Python 程序、并行调度、动态配置、`python -m/-c`、自定义子进程 cwd/env/shell、多工程或多输出目录。发现不支持的外层调度会说明原因。续跑要求原脚本可重跑并跳过已有帧，不清空输出；检查到工程、外层或渲染脚本发生变化会拒绝续跑。不会扫描磁盘并自动执行陌生脚本。

按帧暂停依赖完整 PNG 落盘检测，可能丢弃已开始的下一帧计算；请保持管理器运行到暂停完成。后处理期间暂不提供按帧暂停。原父进程的历史退出码无法补取：首次接入只确认帧完整及脚本退出，后处理结果需查看原日志；由管理器重启的脚本会额外检查退出码。进程资源指标显示当前受管 Blender，外层 Python 与合成程序资源不合计。

## 验证

- 70 项后端/API 测试通过，覆盖完整批次推导、拒绝未知/并行调度、脚本变化、部分帧退出、非零退出与完成判定。
- 真实 Blender 隔离集成测试：新接管与旧单批升级、自动跟踪下一批 PID、整套按帧暂停且无新批次、管理器重启恢复、续渲染保持完成帧哈希、后处理等待和退出码、批次日志、状态重置。
- 浏览器验证一键识别父脚本、完整计划范围与当前批次展示、实时日志、整套暂停和继续入口，无浏览器错误。
- Windows EXE 原生启动就绪；启动清理完成记录、保留图片验证通过。

## 升级

关闭旧管理器，完整解压 `BlenderRenderDesk-v3.4.0-Windows.zip` 后运行 `BlenderRenderDesk.exe`。原 Blender 渲染继续运行，任务数据沿用原目录。进入“本机进程”，对当前正在渲染的 Blender 点击“一键接管”或“接管整套脚本”。识别成功后会显示完整计划；不必每个批次重新接管。
