# v3.3.0 — 一键接管与浅色卡片工作台

## 一键接管

本机进程页点击“一键接管”，自动读取工程、原脚本与启动参数，识别实际 PNG 输出目录、文件名模板、场景和本次帧范围，然后直接加入队列。用户不再需要填写目录、模板和起止帧。识别期间原 Blender 继续渲染。

修复工程保存路径与脚本实际输出路径不一致时，接管提示“输出文件夹不存在”的问题。例如工程总范围 1–1200，脚本通过参数仅渲染 181–240：显示工程 1200 帧、本次 60 帧，并使用脚本计算出的实际输出目录。重新扫描保留脚本范围，不会将本次 60 帧改回 1200 帧。

识别在后台工作线程运行，相同进程的重复点击共用一个识别任务。失败原因会显示在进程行内，不自动结束原进程。

## 新版界面

- 参考 B站网页版的浅色顶栏、分类标签与封面卡片布局，使用 RenderDesk 自己的标识和图标。
- 白色卡片、浅灰背景，粉色主操作与蓝色辅助点缀；设置页、弹窗、日志和滚动条统一样式。
- 渲染任务以最新完成帧作为封面，展示进度、用时、CPU、内存、GPU 和显存。
- 新增名称 / 工程搜索，以及全部、渲染中、已暂停、已完成筛选。筛选时禁用排序，避免改变隐藏任务的位置。
- 桌面右侧集中放置任务预览、开始 / 暂停、编辑、重置和删除。路径及重新扫描收进可展开的“路径与工程配置”。手机自动使用上下布局。
- 卡片最多预加载前 12 个任务的缩略图，并发 2 个请求；完成帧版本不变时复用预览，移出缓存时释放图片 URL。
- 保留底部署名与 B站主页链接。

## 支持范围

自动接管支持可静态识别的单个 `--python` 脚本、顶层同步 `write_still=True` 逐帧 PNG 循环、`sys.argv` 参数、固定步长范围、Path / 常见路径拼接和帧号格式。识别只解析脚本，不导入或重跑脚本，也不读取其他进程的任意 Python 内存。

函数封装、复杂动态配置、动态执行代码、不规则帧列表、多输出目录、多视图及非 PNG 等情况可能无法自动识别，会显示原因。`-a` 动画命令、编辑窗口与其他不支持的启动方式仍仅可监测。原脚本在启动后被修改时，不会套用修改后的配置去接管旧进程。

暂停沿用原机制：首次接管等待下一张完整 PNG 后退出原进程，可能丢弃随后开始的一帧计算；后续使用协作执行器按帧继续。原脚本应可重跑，且不能在初始化时清空输出。旧进程的历史 stdout 无法补接。

## 下载与升级

完整解压 `BlenderRenderDesk-v3.3.0-Windows.zip`，保留 `_internal`，运行 `BlenderRenderDesk.exe`。关闭旧管理器后打开新版即可；关闭管理器不会结束原 Blender 渲染。继续使用原数据目录；使用过 `--data-dir` 时需指定同一路径。

已完成且退出进程的任务仍按 3.2 的规则在下次启动时移出队列，工程、图片及历史日志保留。未完成任务和运行中进程保留。
