# 3.1.0 验证记录

验证环境：Windows 11、Python 3.13.15、Blender 5.1.2、Edge/WebView2。所有测试使用独立临时数据和测试工程，未控制用户正在渲染的任务。

- 31 项后端/API 回归通过：帧事务、完成帧哈希、缺失帧、定时、旧任务导入、认证、Bark、扫描配置与覆盖、60→1200 范围修正、预览完整性、文件事件、限次恢复、密钥轮换、扫描时状态服务响应。
- 真实 Blender 读取 1–1200 帧工程，PNG 16-bit RGBA，保留项目相对路径、关闭扩展名和 50% 分辨率。限定任务渲染 2 帧后，显示任务 2/2 与工程 1200 帧。源 .blend 哈希未变。
- 在测试进程启动后模拟崩溃，Watchdog 等待 5 秒后使用新 PID 自动续渲染，完成帧预览可用，重开管理器任务与完成帧保留。
- 真实 Blender 原有集成测试通过：定时启动、重开管理器后按帧暂停、退出进程、新 PID 继续、完成帧哈希不变、缺帧补渲染；外部脚本接入、首次暂停、协作续渲染、完整日志。
- 浏览器回归通过：多文件导入、原生拖拽接收函数、扫描默认范围、预览、定时、双客户端共享、手机无横向溢出、Watchdog 设置、手动访问密钥使旧设备重新登录、Bark/远程设置，无 JavaScript 错误。物理拖拽未以机器人鼠标操作验证；桌面使用 pywebview 官方 DOM drop/full-path 接口。
- pywebview 原生窗口启动与 UI 就绪检查通过。
- 官方 frpc 0.71.0 的配置 verify、本机 frps 转发验证通过；带工作台密钥访问 200，不带密钥 401，停止后进程退出。未连接公共 frps，实际远程服务需用户填写。

界面截图使用隔离测试任务，预览为测试图像。GPU 计数器可用性仍取决于驱动。后台渲染不承诺固定性能提升。外部任意脚本的内存配置无法自动读取，接管扫描以磁盘工程为准。
- 打包后的 Windows EXE：原生窗口 UI 就绪通过；服务器模式检测到内置 frpc / watchdog，真实扫描 1200 帧工程并渲染指定一帧，JPEG 预览接口通过。
